> 标签应该原子化，一个标签代表一种独特含义。你检查一下所有的标签，重新优化一下」**

## 1. 全量审计（只读，数据实测）

### 1.1 现状口径

- `media_tag`：标签字典，`name` 唯一（utf8mb4_0900_ai_ci，**大小写不敏感**），
  `use_count` 的口径是「`media_video_tag.tag_id = media_tag.id` 的行数」。
- `media_video_tag`：(video_id, facet, name, tag_id)，唯一键 (video_id, tag_id)。
  **历史行 tag_id 全是 NULL**（扫描脚本写的 facet 行），690 行里只有 6 行真正指向字典 ——
  字典里的 `use_count` 是过去按 name 回填的旧快照，与真实引用并不一致。
- **没有相册标签表**：`information_schema` 里查不到 `media_album_tag`，
  全库只有 `media_tag` / `media_video_tag`，所以本次迁移只覆盖视频标签；
  脚本已预留「存在 media_album_tag 就一起备份」。

## 4. 迁移脚本 `QTools/doc/media-import/normalize-tags.js`

```bash
# 预览（默认 --dry-run，不写库、不备份）
node normalize-tags.js --dry-run --mysql=<mysql.exe> --port=3307 --db=qtools --secret=<secret.yml>

# 执行（先 mysqldump 备份，再单事务写库）
node normalize-tags.js --apply   --mysql=<mysql.exe> --port=3307 --db=qtools --secret=<secret.yml>
```

- 参数：`--dry-run`（默认）/ `--apply` / `--map=` / `--backup-dir=` /
  `--json-out=` / `--mysql=` / `--mysqldump=` / `--host= --port= --db= --user=` /
  `--secret=` / `--root-from-db`（无作用，保留参数面一致性）。
  密码：`MYSQL_PWD` > `--secret=`，只经子进程环境变量传递，不打印不落盘（与 `scan-media.js` 同口径）。
- **做法是「按视频重算目标态」而不是逐条改名**：对每个视频算出唯一的「原子名 + 规范 facet」目标行集合，
  只重建有差异的视频，没差异的一行都不碰。这一步同时解决拆分/合并、同概念多 facet 重复、`tag_id` 回填。
- **幂等**：第二遍目标态 = 现状 → `hasWork=false` → 不写库、不产生备份。
- **删除规则**：`use_count=0` 且不在 `keep` 白名单里的标签才删；删之前把它的子标签 `parent_id` 置空。
- **统计**：每个旧标签的处置（保留 / 合并 / 拆分 / 删除）+ 影响视频数 + 行数 + facet 前→后；
  新建 / 删除标签清单；最终标签数与 facet 分组；`--json-out` 同时落一份机器可读统计（管理端弹窗就用它）。

## 5. 管理端入口

- 后端：`POST /api/media/admin/tags/normalize`，body `{dryRun}`（**缺省 true = 只预览**），
  权限 `media:admin:edit`，操作日志「媒体库-标签规范化」。
  实现（`MediaTagNormalizeServiceImpl`）只做三件事：拼白名单命令行 → 跑 `normalize-tags.js` → 回传统计 JSON；
  写库后调 `IMediaIndexService.invalidateSnapshot()`，站端侧栏立刻看到原子标签。
- 管理端界面：**媒体库 → 维护 → 标签体系（原子化）→ 标签规范化**。
  弹窗先跑 dry-run，展示「现状 → 迁移后」「影响面」「处置统计」「备份（执行前会自动备份）」、
  每个旧标签的处置表（旧标签 / 处置 / 映射到 / 视频数 / 行数 / facet 前→后）、9 组原子标签集合，确认后才执行。
- 配置（`application.yml` 与 `config/application.yml` 都加了）：
  `qtools.media.tagNormalizeScript` / `tagNormalizeArgs`（`--port= --secret=`）/
  `tagNormalizeTimeoutSeconds`（180）。

## 8. 已知限制（故意保留的标签与原因）

1. **角色标签 15 个（胡桃 / 甘雨 / 芙宁娜 …）故意保留**：每个是唯一角色名，属于「一种含义」，合并反而违反原子化。
2. **演员标签 3 个（娜娜 / 深田咏美 / 河北彩花）故意保留**：`media_person` 里有同名人物（122/123/124），
   但 `media_video_person` **一行都没有** —— 现在删演员标签就是直接丢信息。
   将来把演员迁进人物体系是另一件事，本次不做。
3. **单次使用但语义唯一的标签保留**（约 60 个：`时间停止` / `未亡人` / `新年主题` / `和室` / `浴室` …）。
   最终是 **103 个**，比需求里预估的 30–60 多：把 103 压到 60 以下只能合并**语义不同**的标签，
   那正是用户抱怨的那类「含义不唯一」。如果确实要更少，建议按下面 4 组「可选合并」再走一轮（每组都丢信息，需要人拍板）：
   - `教师` + `家教` + `秘书` + `上司` → `职场`（丢具体身份）
   - `健身房` + `办公室` + `和室` + `家里` + `浴室` → `室内`（丢场景）
   - `韩国主播` + `韩国女团` + `直播` → `直播`（丢国别 / 形态）
   - `私拍` + `摆拍` + `写真` → `写真`（丢拍摄方式）
4. **`18禁` 放在 `审查` 维度**：`media_video.content_rating` 是分级字段，但标签侧仍有人按 18禁 检索；
   本次不动分级体系，只在标签里保留一条。
5. **「分类」facet 的源目录信息被有意丢掉**：目录仍在 `media_video.folder`，站端/管理端本来就有目录筛选，
   标签侧不必再重复一遍。这也是 chip 数从 145 掉到 103 的主要原因。
6. **前进方向未改**：`scan-media.js`（通用扫描）根本不写标签，新导入不会被污染；
   但旧脚本 `import.js` 仍会按文件名片段写 facet 标签 —— 将来若再用它导入历史 bundle，
   导完请跑一次 `normalize-tags.js --dry-run` 看一眼。
7. **管理端按钮与后端未做端到端点击验证**（本次只做 compile + 前端 build + 脚本级全链路实测）：
   后端由部署方启动，界面上点一次「预览」即可确认（`POST /tags/normalize` 缺省 dryRun=true，不会写库）。
