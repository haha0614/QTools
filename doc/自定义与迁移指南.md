# QTools 自定义与迁移指南

把 QTools 换成「你自己的站点」的完整操作手册。目标读者：第一次拿到这三个仓库、想把站点名、工具、媒体内容和部署环境改成自己的人。

本文只讲**改哪里**，不涉及改代码逻辑。所有路径与字段名都取自仓库现有文件（括号里标了位置），可以直接照着改。

## 0. 这份文档怎么用

三个仓库各管一段：

| 仓库 | 角色 | 主要产物 |
| :--- | :--- | :--- |
| `QTools` | 后端（Spring Boot）+ 部署脚本 | `qtools-admin/target/qtools-admin.jar` |
| `QTools-C` | 前台用户站（Vue 3 + Vite）+ 媒体站手写静态页 | `QTools-C/dist`（含 `dist/media`） |
| `QTools-M` | 管理后台（若依 Vue3） | `QTools-M/dist` |

阅读顺序建议：先用 **第 1 节** 的表格定位「我要改的东西在哪」，再按 **第 2–5 节** 动手，最后照 **第 6 节 checklist** 从零走一遍。

约定：文中 `<home>` 指后端启动参数 `-Dqtools.home` 指向的盘上根目录（缺省 `E:/111`，见 `application.yml:2-12`），所有默认路径都由它推导。

## 3. 工具列表（不用改代码）

工具是**数据**，不是代码：前端首页在挂载时调后端 `GET /toolInfo/list` 渲染卡片。

| 事项 | 位置 / 值 |
| :--- | :--- |
| 数据表 | `tool_info`，建表与初始数据见 `sql/qtools/tool_init.sql:16-27`（字段 `tool_name` / `tool_desc` / `tool_route` / `icon` / `sort` / `status`） |
| 上下架 | `status`：`'0'` 正常、`'1'` 停用（`tool_init.sql:23`）。后端只返回 `status = '0'` 的记录（`qtools-tool/.../ToolInfoServiceImpl.java:22`），停用后前台刷新即消失 |
| 排序 | `sort` 升序（同上） |
| 增删改 | 管理端「工具维护」页面，无需改代码、无需重新构建前端 |

**必须一起改的兜底数据**：`QTools-C/src/views/Home.vue:21-56` 的 `FALLBACK_TOOLS`（当前 4 条：JSON 格式化、文本字数统计、随机密码生成、媒体站）。这份数据只在接口不可用时生效（`Home.vue:105`），但正因如此最容易漏——后端挂了首页会显示**旧的**工具卡片，改完库记得把它改成同一份列表。

新增一个工具页需要三件事：

1. 页面组件放到 `QTools-C/src/views/tool/`（参考 `JsonFormat.vue` / `TextCount.vue` / `PwdGen.vue`）。
2. 在 `QTools-C/src/router/index.js:20-37` 加一条路由（含 `meta.title`）。
3. 在 `tool_info` 里插入一条，`tool_route` 填该路由（如 `/tool/your-tool`）。

`tool_route` 的特殊值：以 `http://` / `https://` 开头或以 `.html` 结尾（如媒体站的 `/media/index.html`）时，前端不做 SPA 路由跳转，而是**整页跳转**（判定逻辑在 `Home.vue:69` 的 `isStaticRoute`）。

## 4. 媒体内容

媒体站 =「磁盘上的媒体目录」+「MySQL 里的索引」+「缩略图」三件套。换自己的内容只需要两个脚本，**不需要**原作者旧 Node 站的 `index.json`：

| 脚本 | 作用 | 依赖 |
| :--- | :--- | :--- |
| `QTools/doc/media-import/scan-media.js` | 递归扫盘 → 写 `media_video` / `media_album` / `media_photo` | `node` + `mysql` 客户端 |
| `QTools/doc/media-import/build-thumbs.js` | 按**库内记录**调 ffmpeg 出缩略图 | `node` + `mysql` 客户端 + `ffmpeg` |

两个脚本都是零依赖（只用 `node:` 内置模块），不需要 `npm install`。

### 4.1 目录约定（以 `scan-media.js` 代码为准）

扫描起点是 `--root` 指向的媒体根目录，脚本对它**只读**（`scan-media.js:33`，只 `readdirSync` / `statSync`）。

| 约定 | 事实来源 |
| :--- | :--- |
| 视频扩展名：`.mp4 .webm .mkv .mov .m4v .avi` | `scan-media.js:43` |
| 图片扩展名：`.jpg .jpeg .png .webp .gif .bmp` | `scan-media.js:44` |
| 只有 `.mp4` / `.webm` 标 `browser_ok=1`（其余进库，但浏览器可能不能直放） | `scan-media.js:45,267` |
| **媒体根下第一级目录名 = 视频分类**；视频直接放在根目录时分类为「默认」 | `scan-media.js:263` |
| **含图片的目录 = 一本相册**；根目录散图也成一本（`dir=''`，标题取根目录名，取不到为「未分组」） | `scan-media.js:271,289,240` |
| 相册 id = `a` + 3 位序号，按目录相对路径自然序从 `a001` 递增 | `scan-media.js:281-283` |
| 照片 `seq` = 目录内文件名自然序（数字感知）从 `0` 递增 | `scan-media.js:286-287` |
| `is_big = 1` 的阈值是 `--big-bytes`，默认 `2097152`（2MB） | `scan-media.js:55,287` |
| 相册封面固定写 `thumbs/p/<albumId>/0000.jpg` | `scan-media.js:296` |
| `rel_path` 超过 700 字符的文件跳过并告警 | `scan-media.js:48,248,277` |
| `--exclude` 按**目录名**排除（任意层级、忽略大小写），默认 `_媒体站,trash,.git,node_modules,thumbs,pv` | `scan-media.js:57,74,225` |
| 不跟随符号链接 / junction（避免环） | `scan-media.js:222-223` |
| 不生成人物：`people` 恒为 0，`media_album.person_id` 留 `NULL` | `scan-media.js:24,335` |

> 换自己的内容时照着摆即可：`<媒体根>/<分类目录>/xxx.mp4`、`<媒体根>/<任意目录>/*.jpg`（每个含图目录自动成册）。

### 4.2 两条命令

```powershell
# 0) 密码只有这一个渠道：环境变量（脚本不读 secret.yml、不打印、不落盘）
$env:MYSQL_PWD = '<数据库密码>'

# 1) 扫盘建库（--dry-run 只统计不写库，不需要数据库与 mysql 客户端）
node <repo>\QTools\doc\media-import\scan-media.js --root=<媒体根> --db=qtools --user=root --host=127.0.0.1 --port=3307

# 2) 按库内记录生成缩略图
node <repo>\QTools\doc\media-import\build-thumbs.js --root=<媒体根> --thumbs=<缩略图根> --ffmpeg=<ffmpeg 路径>
```

- `--port` 注意：脚本默认 `3306`（`scan-media.js:54`），而本项目 `application-druid.yml:9` 的默认端口是 **3307**（`${qtools.db.port:3307}`），本地跑要么显式给 `--port=3307`，要么按实际库填。
- `build-thumbs.js` 的产物路径（`build-thumbs.js:7-9,61-64`）：`v/<videoId>.jpg`（视频封面，`-ss 3` 抽帧，不足 3 秒自动回退 `-ss 0`）、`p/<albumId>/<seq 四位补零>.jpg`（图片缩略图）、`pv/<albumId>/…`（大图预览，仅 `is_big=1`）。
- 缩略图默认增量：目标文件存在且非空即跳过；`--force` 重建全部（慎用）、`--limit=N` 只处理前 n 条（调试，`build-thumbs.js:55-56`）。
- 单条失败不中断，输出 `FAIL <rel_path>: <原因>`，**退出码仍为 0**；只有 ffmpeg 缺失、读库失败这类致命错误才非 0（`build-thumbs.js:20-21`）。
- 参数速查：`scan-media.js:61-75`、`build-thumbs.js:45-57`（`node <脚本> --help` 也能看）。

### 4.3 幂等、危险开关与「哪些记录不会被删」

- **默认 upsert**，按视频 `id`、相册 `id`、照片 `(album_id, seq)` 判重（`scan-media.js:29-30`）。
- upsert **不覆盖**人工或其他工具填好的字段：`hidden` / `person_id` / `note`（`:341-343`）、视频的 `dur/w/h/vcodec`（`:329-331`）、图片的 `w/h`（`:357-358`）。
- **`--truncate` 必须同时给 `--yes`**，否则直接报错退出、不写库（`scan-media.js:414-416`）。它会先清空 `media_photo` / `media_album` / `media_video`（`:316-320`），`hidden`、人物归属等人工状态会一起丢。
- **`--dry-run` 不需要数据库**：只统计并打印条数（`scan-media.js:71,431-433`）。
- **`--dump-sql=<file>`** 把生成的 SQL 写到文件并打印前 20 行，**不执行**；可与 `--dry-run` 同用（`:72,434-443`）。
- 每次导入都会顺手清理：每本相册 `seq >= 当前张数` 的残留行（目录里删过图），以及找不到相册的孤儿图片（`scan-media.js:361-367`）。
- **导入不会删除「磁盘上已消失的相册 / 视频」的库记录**：`DELETE FROM media_album` / `media_video` 只出现在 `--truncate` 分支（`scan-media.js:316-320`）。所以整目录删掉后旧相册仍在库里——要么在管理端手工删，要么 `--truncate --yes` 全量重建（代价是人工状态丢失）。
- 脚本会忽略不认识的参数并打 `WARN`，不会因为多一个参数就不干活（`scan-media.js:106-110,417`；`build-thumbs.js:86`）。

### 4.4 让管理端「重建索引 / 重建缩略图」按钮跑新脚本

只要把配置项指向新脚本即可，Java 侧不用改：

```yaml
qtools:
  media:
    scanScript:  '<home>/project/QTools/QTools/doc/media-import/scan-media.js'
    scanArgs:    '--root=<媒体根> --db=qtools --user=root --host=127.0.0.1 --port=3307'
    thumbScript: '<home>/project/QTools/QTools/doc/media-import/build-thumbs.js'
    thumbArgs:   '--root=<媒体根> --thumbs=<缩略图根> --db=qtools --user=root --host=127.0.0.1 --port=3307'
```

五个必须知道的细节：

1. Java 只在扫描命令里拼 `node <scanScript> --out=<scanOutPath> <scanArgs>`，并**自动过滤 `--truncate`**（`MediaScanServiceImpl.java:353-372`）；缩略图命令是 `node <thumbScript> <thumbArgs>`，并**自动过滤 `--force`**（`:381-400`）。
2. `scanArgs` 里的旧参数（如 `--dir-mode=raw --allow-dup-dir`）新脚本**不认识但会忽略**并告警，行为上不会失败——不过为了让日志干净，请按上面示例换成新脚本自己的参数。
3. `build-thumbs.js` 的 `--thumbs` 必填（也认环境变量 `MS_THUMBS`），`--root` 认 `MS_MEDIA_ROOT`；而 Java 只注入 `MS_FFMPEG`（`MediaScanServiceImpl.java:403-410`），**所以 `thumbArgs` 里必须显式写 `--thumbs=… --root=…`**。
4. 密码只从 `MYSQL_PWD` 读（`scan-media.js:196-203`、`build-thumbs.js:143`），Java 不注入它——**用管理端按钮触发扫描时，后端进程的环境里必须已有 `MYSQL_PWD`**，否则脚本报「未设置 MYSQL_PWD 环境变量」。
5. 输出行是为管理端解析写死的：`videos=… albums=… photos=… people=…` 与 `条数 …`（`MediaScanServiceImpl.java:69-74`）、`START` / `PROGRESS d/d` / `DONE ok= skip= fail=`（`:76-83`）。改脚本输出格式前先看这段正则。

### 4.6 从原作者旧 Node 站迁移（可选，新用户不用看）

旧站把内容导出成一份 `index.json`，仓库里的 `doc/media-import/import.js` 只认这份索引（`import.js:20`），配合旧站自己的两个脚本使用：

```powershell
node <站根>\tools\build_index.js                  # 扫旧站磁盘 → <站根>/data/index.json
node <repo>\QTools\doc\media-import\import.js     # index.json → MySQL（6 张 media_* 表）
node <站根>\tools\build_thumbs.js                 # index.json → 缩略图（不读库）
```

- 只有要**沿用原作者那套目录语义**（`写真/<相册>`、`FRAC_桌面互动壁纸/<子目录>`、`_说明.txt` 的 `【内容】`、视频同名 `.txt` 的 `【概要】` 标签、`≥3 张成册`）时才需要这条路。
- `import.js` 的两个关键点：默认 upsert；`--truncate` 会清 6 张表，而旧的 `--dir-mode=mark` 每次扫描都会改写 `media_album.dir`，会让按目录定位的软删/恢复失效。完整参数见 `doc/media-import/README.md`。
- 其余情况（自己的媒体目录、按目录自动成册、要缩略图）一律走 4.2 的两条命令。

### 4.7 自检：先调 `/config`，先看 `warnings`

`GET /api/media/admin/config`（`MediaAdminController.java:131`，权限 `media:admin:list`）是专门的自检接口，返回：

- `home`：当前生效的 `qtools.home`；
- `media`：`rootPath` / `thumbsPath` / `trashPath` / `ffmpeg` / `nodePath` / `scanScript` / `thumbScript` / `scanOutPath` / `maxTranscode` / `scanArgs`，每项按适用情况带 `value` 以及 `exists` / `readable` / `writable` / `executable` / `fileCount`；
- `counts`：`videos` / `albums` / `photos` / `trashEntries`；
- `warnings[]`：路径不存在、不可写、`ffmpeg`/`node` 缺失、库内条数查不到等（实现见 `MediaAdminServiceImpl.java:643-710`）。

媒体根是**只读**设计，所以 `rootPath` 不可写不报警；`thumbsPath` / `trashPath` 不可写才是异常。自检本身不会 500，异常只落进 `warnings`。

其它可用入口：

| 用途 | 接口 |
| :--- | :--- |
| 条数 / 总字节 / 按分类与人物分布 / 回收站占用 | `GET /api/media/admin/stats`（`MediaAdminController.java:113`） |
| 触发重建索引或缩略图 | `POST /api/media/admin/scan`，body `{"type":"full"}` 或 `{"type":"thumb"}`（`:233`；`type` 只接受这两个值） |
| 看扫描任务与日志尾部（最多 200 行） | `GET /api/media/admin/scan/latest`、`/scan/list`、`/scan/{jobId}` |

### 4.8 媒体站的手写页面

`QTools-C/public/media/` 是一套**手写静态页**（10 个文件，不经 Vue 构建）：`index.html`（视频库）、`photos.html`（图片站）、`me.html`（我的），配套 `app.js` / `photo.js` / `me.js` / `profile.js` 与 `app.css` / `photo.css` / `profile.css`。构建时原样复制到 `dist/media/`，由后端 `/media/` 或 nginx 直接托管。改样式、改文案就改这里，不需要动 Vue 代码。

**改完 JS/CSS 一定要递增版本号**：三个 HTML 里的静态资源都带 `?v=` 参数（当前是 `?v=20261022b`，见 `index.html:9,10,101,102`、`photos.html:9,10,106,107`、`me.html:9,10,45,46`）。浏览器会按 URL 缓存，不递增版本号时你自己这台机器很可能还在用旧文件，排查半天。

## 5. 私密配置与部署

### 5.1 `secret.yml`：四个键

仓库里只有模板 `qtools-admin/src/main/resources/secret.yml.example`，复制成同目录的 `secret.yml` 后填真实值（`secret.yml` 已被 `.gitignore` 排除）：

| 键 | 用途 | 备注 |
| :--- | :--- | :--- |
| `spring.datasource.druid.master.password` | MySQL 密码 | 环境变量 `SPRING_DATASOURCE_DRUID_MASTER_PASSWORD` |
| `spring.data.redis.password` | Redis 口令 | 便携 Redis 默认无密码，**留空即可** |
| `token.secret` | 若依后台（`/login`）JWT 签名密钥 | 环境变量 `TOKEN_SECRET`；模板给了随机生成命令 |
| `qtools.app.jwt.secret` | 用户端（`/api/app/**`）独立 JWT 密钥 | 环境变量 `QTOOLS_APP_JWT_SECRET`；**必须与 `token.secret` 不同**，缺失或相同会启动失败 |

模板里给的都是占位符（`secret.yml.example:11-32`），**不要把真实密钥写进任何会提交的文件**；部署到服务器时建议直接用环境变量或密钥管理服务，而不是上传 `secret.yml`。

注意：`secret.yml` **不覆盖**两个 Node 脚本——它们只从 `MYSQL_PWD` 环境变量取密码（见 4.2、4.4）。

### 5.2 `-Dqtools.home`：所有默认路径的根

`application.yml:2-8` 的注释写明：不带 `-Dqtools.home` 时回落到缺省值 `E:/111`，所有绝对路径都写成 `${qtools.home:E:/111}/...`。所以迁移到别的机器时，最省事的是只改这一个参数：

```bash
java -Dqtools.home=/data/qtools -jar qtools-admin.jar
```

注意两点：路径统一用正斜杠 `/`（Windows 上 Java 与 Node 都接受，避免 YAML 反斜杠转义）；不要把 `qtools.home` 本身写成引用自己的占位符（会触发 `Circular placeholder reference`）。

### 5.3 放到服务器上

- 前端构建：`bin/build-web.bat`（打包 `QTools-C` 与 `QTools-M` 的 `dist`）。
- 后端单端口托管：`application.yml:82-88` 的 `qtools.web.userDist` / `adminDist` / `adminPath`（管理端挂在 `/admin-ui`），三者的原理见 `QTools-M/README.md` 的「单端口托管原理」。
- 用 nginx 反代（或纯静态托管）：细节见 `QTools-M/README.md` 的「nginx 两种方式」；生产环境 `VITE_APP_BASE_API` 是空字符串（同源），不要再引入 `/prod-api` 前缀。
- 后端 `server.port` 默认 `8080`（`application.yml:93`），改端口后要同步改 `QTools-C/.env.development` 的 `VITE_PROXY_TARGET`（当前 `http://localhost:8080`）。

## 7. 已知边界

| 项 | 现状 |
| :--- | :--- |
| 通用导入不写视频元数据 | `dur` / `w` / `h` / `vcodec` 留 `NULL`（不跑 ffprobe），且 upsert 不覆盖已有值（`scan-media.js:16,329-331`）。需要时长/分辨率得另补工具，重扫不会把它们清掉 |
| 通用导入不生成人物 | `people` 恒为 0，`media_album.person_id` 留 `NULL`（`scan-media.js:24,335`）；人物维度要么在管理端手工改归属，要么走旧站 `index.json` 流程（4.6） |
| 删除目录不会删除库记录 | 只有 `--truncate --yes` 会清 `media_album` / `media_video`（`scan-media.js:316-320`）；单册内的图片残留与孤儿图片会被顺手清理（`:361-367`） |
| MySQL 端口默认不一致 | 脚本默认 `3306`（`scan-media.js:54`），后端默认 `3307`（`application-druid.yml:9`）。用 `--port` 对齐，别默认「都能连上」 |
| 管理端触发扫描需要 `MYSQL_PWD` | Java 只注入 `MS_FFMPEG`（`MediaScanServiceImpl.java:403-410`），密码只从环境变量读（`scan-media.js:196-203`） |
| 埋点明细会一直增长 | `media_event` 明细需定期归档：`POST /api/media/admin/stats/archive?before=yyyy-MM-dd`（`MediaStatsController.java:97-98`，搬进 `media_event_archive`，只保留、不提供查询接口） |
| 媒体站前端是手写静态页 | 改 `QTools-C/public/media/` 里的 js/css 后**必须递增 HTML 里的 `?v=` 版本号**，否则浏览器可能继续用旧文件（见 4.8） |
| 旧脚本默认值仍在配置里 | `application.yml:40-49` 的 `scanScript` / `thumbScript` / `scanArgs` 出厂指向原作者旧站脚本与 `--dir-mode=raw --allow-dup-dir`，新部署按 4.4 改掉 |
