# 人物头像「框选裁剪」（P5.55）

## 落库形状

`media_person.avatar_ref`（VARCHAR(512)，**无 DDL 变更**）：

```
a164:4                                  整图（P5.48 老形状，语义与字节都没变）
a164:4#crop=0.2100,0.1300,0.5600,0.5600 裁剪：x,y,w,h 四个 0..1 比例
```

- `x,y` = 左上角在图片里的比例；`w,h` = 宽高占图片的比例。
- 校验：每个值 0..1；`w,h ≥ 0.02`；`x+w ≤ 1`、`y+h ≤ 1`（`MediaAvatarCrop.normalize`）。
- **为什么存比例**：裁剪框是用户在显示尺寸的图上拖的，存像素等于把缩略图分辨率焊进库；
  缩略图一重建（`build-thumbs.js` 换尺寸）像素框就偏了。
- **为什么不用新列**：旧代码解析 `<albumId>:<seq>` 失败会回落到整图（不炸），
  所以「不认识裁剪的旧版本」读新数据 = 整图，天然向后兼容。

## URL

`avatarUrlOf()` 拼出：

```
/api/media/thumb/p/<albumId>/<pad4(seq)>?crop=<x,y,w,h>
```

`MediaFileController` 的 `/thumb/p/{albumId}/{i}` 与 `/thumb/p/{hash}` 都接受可选 `crop`：

- 不带 → **零变化**（原文件、原缓存头）；
- 带 → `MediaAvatarCrop.render` 现裁，落 `<thumbs>/avcrop/<sha1>.jpg`（键含源文件 size+mtime，
  缩略图重建自动失效，不需要清理任务），压缩质量 0.9；
- 参数非法 → **400**（不静默退成整图：用户明确选了一个框，悄悄给整图更难查）。

## 前端

`PersonAvatarDialog.vue` 点相册图 → 裁剪态：

- 拖拽框选（松手收成正方形；点一下不拖 = 中心 60%）；
- 缩放滑块 20–100%（占短边百分比）；
- 三档：脸部（42%，中心偏上 42%）/ 中心（60%）/ 整图（不写 `#crop`）；
- 预览用 `pv` 大图（`scale=1600:-2`），后端裁 `p` 缩略图（`scale=400:-2`）——
  两者等比缩放比例一致，框的位置即后端裁的位置。

## 实测

同一张图：`/thumb/p/a161/0000` = 400×534；加 `?crop=0.2917,0.2625,0.4208,0.3156` = 168×169
（168/400 = 0.420 ≈ 参数 0.4208）。越界参数 400、无参 200。
