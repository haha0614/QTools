# 媒体库内容自动分级（P6.02）

给**现有内容**批量打上 `general（大众级）/ guidance（家长指导级）/ restricted（限制级）`，
不再一条条手点。两个入口、一套判定：

| 入口 | 谁用 | 怎么调 |
| --- | --- | --- |
| 管理端「媒体库 → 维护 → 内容分级（自动分级）」 | 站长日常 | 弹窗里先预览，确认后「确认执行」 |
| 脚本 `QTools/doc/media-import/classify-rating.js` | 部署机 / 工单留痕 | 调**同一个**后端接口，打印同一份报告 |

> **唯一真源**：词表与匹配逻辑只存在于后端（`rating-rules.json` + `MediaRatingRules`）。
> 脚本不复制词表、不做匹配，因此「脚本判出来的」与「按钮判出来的」永远一致。

---

## 1. 判定口径（三条硬规则）

1. **最严优先**：同一条目命中多档 → 取 `general < guidance < restricted` 中最严的一档，与命中顺序无关；
2. **general 词不翻案**：general 与 restricted 同时命中一定取 restricted（宁可高估）。
   general 词的作用是让「为什么是大众级」可解释，不是用来「压回」更严的档；
3. **一条不命中 = 不确定**：交给本地模型兜底；模型没给出可用档位 → **保持原值**（默认 general）并写进报告。

匹配字段：`title` 标题 / `folder` 视频目录名 / `dir` 相册目录 / `path` 相对路径 / `tag` 标签名。
相册按内容聚合：册的标题与目录判一次，**名下每张照片的 rel_path 各判一次**，一路取最严 ——
所以「整本普通写真里混了一张裸拍」也会被顶到限制级。

## 2. 词表：`QTools/qtools-media/src/main/resources/rating-rules.json`

```json
{
  "rules": [
    { "id": "restricted-masturbation", "rating": "restricted", "mode": "contains",
      "pattern": "自慰", "fields": ["title","folder","dir","path","tag"],
      "note": "自慰是明确的成人性行为，与「穿着暴露」不是一回事" },
    { "id": "guidance-swimsuit", "rating": "guidance", "mode": "regex",
      "pattern": "泳装|泳衣|比基尼|水着|swimsuit", "note": "..." }
  ]
}
```

* `mode`：`contains`（包含，大小写不敏感）或 `regex`（正则，`CASE_INSENSITIVE`）；
* `fields`：可选，缺省 = 五个字段全参与；
* `note`：**必填**，写清「为什么这一档」——报告里的可解释性靠它；
* 每条规则的 `id` 必须稳定且唯一（命中统计按 id + 命中词聚合）。

改词表不用改代码：

* 开发期改 classpath 里的 `rating-rules.json`，重启后端生效；
* 部署期用 `qtools.media.rating.rulesFile=E:/path/rating-rules.json` 指向外部文件，**每次请求按文件重读，改词不必重启**；
* 词表写坏（JSON 语法 / 缺 id / 非法档位 / 正则写错）→ 接口回 **503 + 具体原因**，绝不静默用空词表把全站判成大众级。

## 3. 模型兜底层（只处理「规则一条不命中」的条目）

* 模型：`qtools.media.llm.model`（现网 `qwen2.5:3b`，Ollama 本机）；
* 提示词：三档定义 + 一句判断标准（露骨行为/裸露性器官 → restricted；只暴露/性暗示 → guidance；都没有 → general），
  要求**只输出一个英文档位单词**；
* 参数：`temperature 0.1`、`num_predict 8`（一个单词足够，给多了模型开始自我解释）；
* 预算：`qtools.media.rating.llmConcurrency=2`、`llmTimeoutMs=15000`（单条超时即放弃该条）、
  `llmMaxItems=300`（一轮最多送多少条，超出记 `truncated`）；
* 失败（超时 / 连不上 / 回复不可解析）→ 该条**保持原值**并进报告 `failedSamples`，绝不猜一档写库；
* 解析宽松但方向从严：回复里出现 `restricted` 就按限制级，其次 `guidance`，最后 `general`。

## 4. 接口

```
POST /api/media/admin/rating/classify     （权限 media:admin:edit）
body: { dryRun?: bool, only?: "all"|"video"|"album", limit?: int, useLlm?: bool, force?: bool }
```

* **`dryRun` 缺省 true**：不传就是预览，只读库、不写库；
* `force` 缺省 false：默认只把 `general`（含未分类）升级成更严的档，**已人工设过 guidance / restricted 的条目不动**；
* 回包（摘要）：`counts`（跑完后的每档计数）、`existing`（跑之前）、`sources`（规则/模型/保持原值各多少条）、
  `hitsTop`（命中词 Top20）、`samples`（20 条样例：标题 → 判定 → 理由）、
  `llm`（候选数 / 判成功 / 失败 / 耗时 / 10 条样例）、`applied`（可写 / 保护 / 实际写入条数）。

## 5. 脚本

```bash
# 1) 预览（生产只跑这一步）
node QTools/doc/media-import/classify-rating.js --token=<管理端 JWT> --use-llm \
     --secret=QTools/qtools-admin/src/main/resources/secret.yml --db=qtools
# 2) 确认分布后写库
node QTools/doc/media-import/classify-rating.js --token=<管理端 JWT> --use-llm --apply
# 3) 只重判相册 / 只跑前 50 条
node QTools/doc/media-import/classify-rating.js --token=<管理端 JWT> --only=album --apply
node QTools/doc/media-import/classify-rating.js --token=<管理端 JWT> --limit=50
```

脚本里的 `--mysql/--host/--port/--db/--secret` **不参与判定**，只用于跑完后独立核对
`select content_rating, count(*) group by`（这是 apply 之后唯一能证明「真写进去了」的证据）。

## 6. 已知限制

1. **模型兜底不确定**：`qwen2.5:3b` 对「mmexport1793…」这类纯 ID 标题只能按目录名猜，判 general；
   同一批数据两次跑可能有个别条目在 general / guidance 之间摆动（temperature 0.1 仍有随机性）；
2. **词表是「宁可高估」的口径**：写真类整册容易被一张露骨照片顶到限制级（这是有意的聚合口径）；
3. **相册只看 rel_path 与标题**，不看画面内容；真要按画面判需要视觉模型（P5.53 的 vision 链路，本功能未启用）；
4. **一次跑批同步返回**：现网 409 条（239 视频 + 170 相册、约 1 万张照片）规则层 1-2 秒；
   开模型兜底后取决于不确定条数（11 条约 0.5-8 秒）。条目数上千时应改用脚本 + `--limit` 分批；
5. 分类只写 `content_rating` 列，**不动** `rating`（0-100 的评分）与其它任何列。
